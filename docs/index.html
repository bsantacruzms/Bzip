Why BoltZip is different

🧠

Automatic hardware optimization

Profiles your CPU cores, RAM and storage (NVMe/SSD/HDD/network) and auto-tunes threads, window size, buffers and codec, per job. And it tells you why.

🔒

Modern authenticated encryption

The native .bz format uses XChaCha20-Poly1305 with Argon2id key derivation. Tampering and wrong passwords fail loudly, not silently.

⚡

Fast modern codec

Built on Zstandard, which beats classic Deflate/LZMA on the speed-vs-ratio curve and scales across every core.

🆓

Free, open, no nag screens

No ads, no upsells, no trials. MIT-spirited and fully open source.

📦

Portable & scriptable

Single-file executables, a friendly bz CLI, and a Windows right-click menu when you install it.

🌍

Cross-platform core

One Fluent desktop app for Windows, macOS and Linux, powered by the same .NET engine.

Video & media files

Videos, photos and music are already compressed by their own codecs (H.264/H.265, JPEG, MP3/AAC). No lossless archiver, not BoltZip, 7-Zip or WinRAR, can meaningfully shrink them, so every tool lands near 100% of the original size. The honest win is time: BoltZip detects already-compressed media and stores it at full speed instead of burning CPU trying to compress the incompressible.

Actually make videos smaller, on your GPU

To truly shrink a video you have to re-encode it. BoltZip does that with your graphics hardware (NVIDIA NVENC, AMD AMF, Intel Quick Sync, Apple VideoToolbox on macOS) at a visually-lossless setting that looks identical to the source. No other mainstream archiver re-encodes video at all, so this is the one place BoltZip makes your files dramatically smaller and faster to send.

Run it yourself: bz video myclip.mp4 (needs FFmpeg). Re-encoding is lossy by definition, but at the visually-lossless setting the difference is imperceptible; when you need a byte-exact copy, archive it losslessly instead.

Security by design

Archivers are a favorite malware entry point. 7-Zip alone shipped serious fixes recently, here are two real ones, and how BoltZip’s architecture avoids whole classes of such bugs.

CVE-2024-11477 · CVSS 7.8

7-Zip: Zstandard decode RCE

An integer underflow in 7-Zip’s native Zstandard decompressor allowed remote code execution from a crafted archive (fixed in 7-Zip 24.07).

CVE-2025-0411 · CVSS 7.0 · exploited

7-Zip: Mark-of-the-Web bypass

Extracted files lost the “downloaded from the internet” flag, letting malware skip SmartScreen (fixed in 24.09; listed in CISA’s Known Exploited Vulnerabilities catalog).

BoltZip · by construction

How BoltZip mitigates

Memory-safe engine: the whole pipeline is managed .NET, bounds-checked, so the integer-underflow / buffer-overflow class behind native RCEs (like the Zstd bug at left) is structurally avoided.

Authenticated format: .bz uses XChaCha20-Poly1305 (AEAD) + Argon2id; tampering, truncation and reordering fail loudly, and extraction guards against path traversal (“Zip Slip”).

Sources: NVD, CVE-2024-11477 (CWE-191, integer underflow) and CVE-2025-0411 (CWE-693, in CISA KEV). No software is invulnerable, but a managed, authenticated, fully open-source design removes entire categories of risk instead of patching them one by one.
